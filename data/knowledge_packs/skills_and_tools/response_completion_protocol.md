# Response Completion Protocol

Use this protocol for local tool, engineering, benchmark, and operations work.

## Required Closeout

Every substantial answer should include:
- objective
- actions taken or recommended
- validation method
- risk or rollback note when applicable
- next step

## Completion Gate

Before final output:
- Check whether the user asked for code, commands, architecture, testing, rollout, or comparison.
- Confirm each requested artifact exists in the answer.
- Do not mark the response complete if a section is missing.
- Prefer concise but complete output over long unfinished output.
