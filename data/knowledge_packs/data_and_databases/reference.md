# Data & Databases Cheat-Sheet

## Schema
- Normalize by default (3NF); denormalize only for measured read hotspots, keep source of truth.
- Pick a stable surrogate PK (`INTEGER`/`BIGINT` autoinc or UUID); never a mutable natural key.
- `NOT NULL` + sane `DEFAULT` on every column you can; NULL means "unknown," not 0/"".
- Index columns you filter/join/sort by; composite index order = equality cols first, then range. FKs need indexes too.

## Queries
- ALWAYS parameterize: `cur.execute("...WHERE id=?", (id,))`. Never f-string/`%`-format SQL → injection.
- N+1: looping queries per row. Fix: one JOIN or `WHERE id IN (...)`; in ORM use eager load (`selectinload`/`joinedload`).
- Wrap multi-write logic in a transaction; commit once, rollback on error (atomicity).
- JOIN for combining rows; correlated subquery often slower—prefer JOIN or window function.
- `COUNT(*)` counts rows; `COUNT(col)` skips NULLs. `x = NULL` is never true—use `IS NULL`.

## SQLite vs Postgres
- SQLite: enable WAL (`PRAGMA journal_mode=WAL`) for concurrent readers; types are dynamic (declared type is a hint), enforce in app. One writer at a time—not for high write concurrency.
- Use SQLite for embedded/single-node/tests; Postgres for concurrency, types, JSONB, real constraints.

## ORM (SQLAlchemy)
- Lazy attribute access after session close → `DetachedInstanceError` or N+1. Load what you need eagerly.
- Session = unit of work: open per request, commit/rollback, close. Don't share across threads.
- Always review autogenerated migrations—Alembic misses renames, server defaults, enum/type changes.

## Migrations (safe, online)
1. Add nullable column / new table (additive). 2. Backfill in batches. 3. Switch app to write/read it. 4. Add `NOT NULL`/drop old later.
- Never rename+drop in one deploy; old code still runs.

## Dates & JSON
- Store UTC (`TIMESTAMPTZ`); convert at display edge. Never store naive local time.
- JSON/JSONB for sparse/flexible data; index with expression/GIN. Don't put queried-by-key fields in JSON—use real columns.
